    Vue.js • Fondamentaux et comparaison Angular / React

    Positionnement

    Vue occupe le terrain intermédiaire : la structure d'Angular (template, directives, outillage officiel) avec la légèreté de React. Très présent dans les ESN et les DSI françaises, souvent pour moderniser des écrans internes sans partir sur Angular complet.

    Vue 2 ou Vue 3 • la première question à poser

    Vue 2 Vue 3
    Sortie 2016 2020
    Support fin de vie depuis fin 2023 version courante
    Réactivité Object.defineProperty (getters/setters) Proxy
    Organisation du code Options API (data, methods, computed) Composition API (setup, ref)
    TypeScript support ajouté après coup, imparfait conçu avec TS
    Racine du template une seule racine obligatoire fragments autorisés
    Store Vuex Pinia
    Build webpack / vue-cli Vite

    Limites levées par la réactivité Proxy de Vue 3 : en Vue 2, l'ajout d'une propriété à un objet ou l'affectation par index dans un tableau n'était pas détecté - d'où Vue.set(obj, 'cle', valeur). En Vue 3, le proxy intercepte tout.

    Sur un projet existant

    Un projet encore en Vue 2 avec Vuex et vue-cli est un projet hors support. La migration Vue 2 → 3 se fait par étapes : Vue 2.7 (qui apporte la Composition API), remplacement des APIs supprimées (filtres, $on/$off, Vue.set), puis passage à Vue 3 et à Vite. C'est un chantier à part entière, pas une montée de version.

    Anatomie d'un composant • Single File Component

    Un fichier .vue réunit les trois préoccupations dans un seul fichier, avec un scope CSS local - c'est la principale différence de forme avec Angular (trois fichiers) et React (JSX + CSS-in-JS ou fichier séparé).

    <script setup lang="ts">
import { ref, computed, onMounted } from 'vue'

// props typées
const props = defineProps<{ userId: string }>()
// événements typés
const emit = defineEmits<{ (e: 'selected', user: User): void }>()

const user = ref<User | null>(null)
const chargement = ref(false)

const nomAffiche = computed(() => user.value?.nom.toUpperCase() ?? '-')

onMounted(async () => {
  chargement.value = true
  user.value = await fetchUser(props.userId)
  chargement.value = false
})
</script>

<template>
  <div v-if="chargement">Chargement…</div>
  <div v-else-if="user" @click="emit('selected', user)">
    <h2>{{ nomAffiche }}</h2>
  </div>
</template>

<style scoped>
h2 { color: var(--couleur-titre); }
</style>

    Réactivité • le cœur du modèle

    import { ref, reactive, computed, watch, watchEffect } from 'vue'

const compteur = ref(0)                   // valeur primitive → .value obligatoire
const filtre = reactive({ page: 1, taille: 20 })  // objet → accès direct

const double = computed(() => compteur.value * 2) // dérivé, mis en cache

watch(compteur, (nouveau, ancien) => {    // dépendance explicite
  console.log(ancien, '→', nouveau)
})

watchEffect(() => {                       // dépendances détectées automatiquement
  chargerPage(filtre.page)
})

    Les trois règles qui évitent les erreurs classiques :

    • ref → toujours .value dans le code, jamais dans le template (déballage automatique)
    • reactive ne fonctionne que sur des objets, et perd sa réactivité si on le déstructure (const { page } = filtre casse le lien → utiliser toRefs)
    • un computed doit rester pur : pas d'appel HTTP, pas de mutation

    Le même modèle mental que les Signals Angular

    ref / computed / effect de Vue et signal / computed / effect d'Angular 16+ sont deux implémentations de la même idée : de la réactivité fine-grained, sans détection de changement globale ni comparaison d'arbre virtuel. Qui maîtrise l'un comprend l'autre en une heure.

    Directives de template

    Directive Rôle Équivalent Angular
    v-if / v-else-if / v-else rendu conditionnel (retire du DOM) @if
    v-show garde dans le DOM, bascule display [hidden]
    v-for="(x, i) in liste" :key="x.id" itération @for ... track
    :prop="valeur" (v-bind) liaison descendante [prop]
    @click="handler" (v-on) événement (click)
    v-model="champ" liaison bidirectionnelle [(ngModel)]
    v-html injection de HTML brut [innerHTML]

    v-html et XSS

    v-html insère du HTML sans échappement. Sur une donnée venant d'un utilisateur ou d'une API tierce, c'est une XSS directe. Vue n'assainit rien : il faut passer par DOMPurify, ou ne pas utiliser v-html.

    v-if retire l'élément du DOM (coût de création à chaque bascule) ; v-show ne fait que masquer (coût mémoire constant). Bascule fréquente → v-show, condition rare → v-if.

    Communication entre composants

    flowchart TD
    P[Composant parent] -->|props : descendant| E[Composant enfant]
    E -->|emit : ascendant| P
    P -->|slots : contenu injecte| E
    A[Ancetre] -->|provide / inject| D[Descendant lointain]
    S[(Store Pinia)] <--> P
    S <--> E
    • props / emit - le contrat par défaut, unidirectionnel descendant, événements ascendants
    • slots - le parent injecte du contenu (équivalent de ng-content / children)
    • provide / inject - évite de faire descendre une prop sur cinq niveaux ; à réserver aux dépendances transverses (thème, configuration)
    • store Pinia - état partagé entre branches distantes de l'arbre

    Pinia • gestion d'état

    export const useFacturesStore = defineStore('factures', () => {
  const factures = ref<Facture[]>([])
  const chargement = ref(false)

  const impayees = computed(() => factures.value.filter(f => !f.payee))

  async function charger(clientId: string) {
    chargement.value = true
    try {
      factures.value = await api.get(`/clients/${clientId}/factures`)
    } finally {
      chargement.value = false
    }
  }

  return { factures, impayees, chargement, charger }
})

    Pinia contre Vuex : plus de mutations, plus de namespaced: true, typage TypeScript naturel, découpage en stores indépendants, et support du devtool. Vuex n'est plus recommandé pour un nouveau projet.

    À comparer avec NgRx côté Angular : NgRx impose le triptyque actions / reducers / effects (Redux), Pinia se contente d'un objet réactif avec des fonctions. Moins de cérémonie, moins de traçabilité formelle. → NgRx

    Écosystème

    Besoin Solution officielle ou dominante
    Build / dev server Vite (créé par l'auteur de Vue)
    Routing Vue Router - routes imbriquées, guards, lazy loading
    État global Pinia
    SSR / méta-framework Nuxt (équivalent de Next côté React)
    Tests unitaires Vitest + @vue/test-utils
    Tests end-to-end Playwright, Cypress
    Composants UI Vuetify, PrimeVue, Quasar, Element Plus

    Vue, Angular, React • la comparaison honnête

    Angular React Vue
    Nature framework complet bibliothèque de vue framework progressif
    Langage TypeScript imposé JS ou TS JS ou TS
    Template HTML + directives JSX (JS dans la vue) HTML + directives
    Routing / HTTP / forms fournis et intégrés à choisir dans l'écosystème routing et store officiels
    Injection de dépendances native, complète conventions et contextes provide / inject, plus léger
    Réactivité Zone.js, puis Signals re-render + hooks, VDOM Proxy fine-grained, VDOM optimisé
    Courbe d'apprentissage forte moyenne la plus douce
    Terrain typique en France grandes DSI, bancaire startups, tech applications métier, refonte progressive
    Migration entre majeures ng update, cadence de 6 mois codemods, rythme libre Vue 2 → 3 = vrai chantier

    Le critère de choix • « pourquoi Vue ? »

    « Vue est un bon choix quand il faut moderniser une interface progressivement : on peut monter Vue sur une seule page d'une application existante, sans réécrire le reste. Il apporte le routing et un store officiels - donc moins de décisions à justifier qu'avec React - pour un coût d'entrée inférieur à Angular. Angular reste plus adapté quand il y a beaucoup d'équipes et un besoin de cadre imposé ; React quand l'écosystème de la boîte est déjà React. »

    Ce que vous devez savoir vérifier sur un projet Vue

    1. Version - Vue 2 (hors support) ou Vue 3
    2. API utilisée - Options API ou Composition API, et si les deux cohabitent
    3. Store - Vuex (à migrer) ou Pinia
    4. Build - vue-cli/webpack ou Vite
    5. TypeScript - réellement typé, ou any partout
    6. Tests - Vitest en place, et bloquants en CI ou non

    Questions typiques, réponses courtes

    « Quelle différence entre Vue et Angular ? » Angular est un framework complet et prescriptif : TypeScript imposé, injection de dépendances, routing, HTTP et formulaires intégrés, cadence de deux majeures par an. Vue est progressif : on peut l'ajouter à une page existante, le routing et le store sont officiels mais optionnels, et la courbe d'apprentissage est plus douce. Angular convient quand plusieurs équipes ont besoin d'un cadre imposé ; Vue quand il faut moderniser sans tout réécrire.

    « Et par rapport à React ? » React est une bibliothèque de vue : tout le reste - routing, état global, formulaires - est un choix d'écosystème. Vue apporte des solutions officielles, ce qui réduit le nombre de décisions à justifier. Côté template, React met le HTML dans le JavaScript (JSX), Vue garde un template HTML avec des directives.

    « Vue 2 ou Vue 3 ? » Vue 2 est en fin de vie depuis fin 2023. Vue 3 apporte la Composition API, une réactivité fondée sur Proxy - donc sans les angles morts de Vue 2 sur l'ajout de propriétés et les tableaux -, un vrai support TypeScript, Pinia à la place de Vuex et Vite à la place de vue-cli.

    « ref ou reactive ? » ref pour tout, par défaut : il fonctionne sur les primitives comme sur les objets, et il résiste à la déstructuration. reactive ne s'applique qu'aux objets et perd sa réactivité si on le déstructure - il faut alors passer par toRefs. En pratique, s'en tenir à ref évite la plupart des bugs de réactivité.

    « Vuex ou Pinia ? » Pinia. C'est le store officiel depuis Vue 3 : plus de mutations, plus de modules nommés, un typage TypeScript naturel. Vuex n'est plus recommandé pour un nouveau projet ; sur un projet existant, sa migration est un chantier à part entière.

    « Quels sont les pièges de sécurité côté Vue ? » v-html en premier : il insère du HTML sans échappement, donc une XSS directe sur une donnée non maîtrisée. Ensuite, le stockage des jetons côté navigateur - comme pour tout framework front, un jeton en localStorage est lisible par n'importe quel script de la page.

    « Comment se passe une migration Vue 2 → Vue 3 ? » Par étapes : d'abord Vue 2.7, qui apporte la Composition API sans changer de majeure ; puis la suppression des APIs disparues (filtres, $on / $off, Vue.set) ; puis Vue 3, Pinia et Vite. Ce n'est pas un npm update : c'est un projet, à planifier comme tel.
